# Protocol v1

P0 freezes the first executable wire contract. The phase plan takes precedence over the architecture PDF's illustrative `v`/`senderPeerId`/`body` example. Those aliases are rejected to avoid accepting two formats. Authentication, admission, replay windows and channel ownership are P1/P2 responsibilities, not properties of successful parsing.

## Signaling

Each message has exactly `version`, `type`, `roomId`, `peerId`, `messageId`, `epoch`, `seq`, `sentAt`, `payload`. Version is numeric `1`; IDs are RFC UUIDs; epoch/seq are uint32; sentAt is an ISO timestamp with timezone. SentAt is diagnostic, never an authorization clock. Sequence increases per authenticated sender/epoch; reconnect must not reuse a stale epoch or wrap counters. Epoch coordination is deferred to P1/P2.

Maximum encoded message: 65,536 UTF-8 bytes, checked before JSON parsing. Unknown keys are rejected. SDP is capped at 49,152 UTF-8 bytes and ICE text at 4,096; the full cap always applies. Parse errors never echo input. P1 must verify peer association against authenticated membership.

| Type                                         | Payload                                                                                                              |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| JOINED                                       | `approval: pending / approved`                                                                                       |
| PEER_PENDING / PEER_APPROVED / PEER_REJECTED | `candidatePeerId: UUID`                                                                                              |
| SDP_OFFER / SDP_ANSWER                       | `sdp: bounded nonempty string`                                                                                       |
| ICE_CANDIDATE                                | `candidate: string`, `sdpMid: string or null`, `sdpMLineIndex: uint16 or null`; empty candidate is end-of-candidates |
| RENEGOTIATE                                  | `reason: ice-restart / new-connection`                                                                               |
| ROOM_CLOSED                                  | `reason: owner-closed / expired / revoked`                                                                           |
| ERROR                                        | `code`, bounded `message`, `retryable: boolean`                                                                      |

File bytes, labels, manifests and block ACKs are excluded. Peer data-channel control schemas ship separately in P3/P5. HTTP errors use `{ code, message, requestId, retryable }`. Credentials must not appear in query strings, analytics or logs.

## Binary DATA frame

Multibyte integers use network (big-endian) order. Each RTCDataChannel message contains exactly one frame. The initial total ceiling is **16,384 bytes including its 64-byte header**, leaving 16,320 payload bytes. This reconciles the master plan's total limit with the phase plan's payload starting point conservatively. Negotiation may reduce the ceiling; v1 cannot increase it without a protocol decision. Verification blocks are 1,048,576 bytes.

| Offset | Bytes  | Field               |
| ------ | ------ | ------------------- |
| 0      | 4      | Magic ASCII `MDP1`  |
| 4      | 1      | Version `1`         |
| 5      | 1      | Kind `1` (DATA)     |
| 6      | 2      | Flags; zero         |
| 8      | 16     | Transfer UUID       |
| 24     | 16     | File UUID           |
| 40     | 4      | Connection epoch    |
| 44     | 4      | Block index         |
| 48     | 4      | Offset within block |
| 52     | 4      | Payload length      |
| 56     | 4      | Frame sequence      |
| 60     | 4      | Reserved; zero      |
| 64     | length | Nonempty payload    |

Reject unknown versions/kinds, nonzero flags/reserved fields, invalid UUIDs/uint32 values, short/trailing bytes, ceiling violations, empty payloads and block-crossing frames. Empty files have no DATA frames in P3. Decode copies only the bounded payload. Headers do not prove membership, manifest bounds, freshness, integrity or commitment; P3 validates active transfer context.

Fixtures use synthetic UUIDs and public text. The binary golden fixture specifies bytes independently of the encoder. Wire changes must update this spec, fixtures and negotiation together.
