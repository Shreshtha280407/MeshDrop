# Configuration and secret handling

Local static server/provider secrets belong in `apps/signaling/.env`, beside `wrangler.jsonc`. That file is ignored and was created locally with mode 0600. Copy the committed `.env.example` for a fresh setup; the example has public development settings and no secret values. Never put private keys in source, Wrangler `vars`, fixtures, reports, command arguments, or a frontend `VITE_*` variable.

Direct P1/P2 sessions need no external provider key or shared signing secret. Optional coturn relay uses `TURN_SHARED_SECRET` only in the ignored server `.env`; the browser receives an expiring username/HMAC credential, never this shared secret. Ephemeral non-extractable ECDSA signing keys are generated per connection epoch in browser memory and are never persisted as configuration. The Worker generates 32-byte random owner/invitation capabilities; the receiver generates a separate random local peer capability before joining, allowing the same interrupted join request to be retried without the server storing a recoverable bearer. These are short-lived runtime credentials, not deployment configuration. They remain in browser memory, are sent over authorized HTTPS/WSS requests, and only domain/room/peer-scoped SHA-256 verifiers enter SQLite. Closing a tab loses local admission; recovery of browser credentials will be addressed explicitly in later phases.

Invitations use URL fragments and are removed from browser history immediately on opening. The application has no third-party scripts/analytics and uses a no-referrer policy. Browser storage and room event logs do not retain raw credentials. WebSocket tickets use `Sec-WebSocket-Protocol`, never URL query parameters, and the server negotiates only the public `meshdrop.v1` protocol back. TLS remains required outside loopback development; anyone with a copied bearer can use its scoped authority until expiry/revocation, so share invitations privately.

`.gitignore` excludes `.env`, `.env.*`, `.dev.vars`, `.dev.vars.*` and `.aws/` at every depth. Only `.env.example` is exempted. `pnpm check:secrets` checks tracked/unignored environment files, ignore coverage and common embedded credential/private-key patterns. This is a preventive project check, not a guarantee that every possible secret format can be detected. CI runs it before tests. Runtime data is also excluded from Git through `.wrangler/`, `test-results/` and `playwright-report/` ignores. Live browser tests disable network traces, and saved invitation screenshots are masked.

For eventual production, use encrypted Worker secret bindings supplied from the appropriate secret-management environment rather than publishing local `.env` files. This phase performs no deployment. Local environment-file behavior follows the [Cloudflare secrets documentation](https://developers.cloudflare.com/workers/configuration/secrets/).
