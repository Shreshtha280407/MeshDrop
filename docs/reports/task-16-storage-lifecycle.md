## Architecture retained and persistent-object inventory

P4's OPFS/IndexedDB/Web Lock architecture, schema version and wire protocol remain in place. The lifecycle remains offer/consent → prepare metadata → OPFS files → exact block write/readback/hash/flush → atomic ledger commit → ACK eligibility → interruption → rehash/reconcile → fresh admission/pairing/source proof → missing-only resume → whole-file hash → receipt → optional external export.

| Persistent object               | Creation/update                                                                                        | Retention/recovery                                                                                                                     | Deletion/failure handling                                                                                             |
| ------------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| IDB `transfers`                 | Preparation before OPFS; block commits update expiry; finalization/receipt/reconciliation update state | Initial preparation deadline, refreshed only by successful block commit; 24 hours or seven days; strict parsing and rehash on recovery | Locked conditional tombstone, OPFS removal, then IDB removal; malformed entries reported for explicit scoped deletion |
| IDB `manifests`                 | Atomically created with transfer metadata; immutable normalized identity                               | Validated transfer ID and canonical manifest digest; no network authority                                                              | Receiver purge, or orphan cleanup if transfer row is absent                                                           |
| IDB `blocks`                    | Exact file/index/length/digest committed only after readback/flush                                     | Every row revalidated against manifest bounds and stored SHA-256; missing/corrupt rows discarded                                       | Atomic ledger reconciliation, receiver purge, or orphan metadata cleanup                                              |
| Checkpoint digest/finalized IDs | Derived from rehashed valid ranges/files in transfer metadata                                          | Cached counters and flags are insufficient evidence; full-file hash still required                                                     | Recomputed, invalidated or removed with receiver metadata                                                             |
| Completed receipt               | Persisted after the transfer receipt handshake                                                         | Restored only when the exact manifest and all finalized bytes remain consistent                                                        | Removed on mismatch or receiver deletion; not an offline identity or admission credential                             |
| OPFS transfer directory         | `meshdrop-receiver-v1/<transfer UUID>` after discoverable metadata                                     | Protected by `meshdrop-store:<UUID>` Web Lock                                                                                          | Validated directory only; retryable tombstone, or locked/rechecked proof of missing transfer record                   |
| OPFS storage directory/files    | `<storage UUID>/<file UUID>`; peer filenames never select paths                                        | Bounded block reads; missing/truncated/corrupt bytes become missing ranges, unledgered tail trimmed                                    | Scoped transfer-root removal also handles preparation stopped before a child existed                                  |
| IDB `sources`                   | Sender preparation stores manifest/digest/expiry, never a persisted File or permission                 | Independent 24-hour default; exact name/size/full SHA-256 reselection; at most 32 with existing earliest-expiry eviction               | Conditional expiry or explicit Forget; never removes receiver data                                                    |
| Diagnostics IDB                 | Existing strict allowlisted reports, separately from checkpoints                                       | At most 10 reports, 512 KiB/report, 4 MiB aggregate, seven days; existing tests retained                                               | Existing expiry/pruning/explicit history deletion; not changed by Task 16                                             |
| Service-worker cache            | Existing exact public-shell allowlist                                                                  | No capability, transfer, receipt, diagnostics or TURN response cache                                                                   | Existing update/cache tests retained; no new sensitive cache path                                                     |
| External Downloads/Files/export | User-directed verified-file export                                                                     | Outside MeshDrop's retention authority                                                                                                 | Never deleted by checkpoint cleanup; independently hashed in restart tests                                            |

Receiver capacity remains 64 discoverable records. Orphan metadata discovery streams distinct keys, at most 128 IDs per reconciliation pass; OPFS directory enumeration is streamed. No whole-file JS buffer or new persistent format is introduced. The browser restart fixture is 4 MiB + 17 bytes, not a repeat of P4's 300 MiB experiment.

## Confirmed defects and corrections

Each application defect below was exercised through actual production classes/RPC/UI before its correction. Failure-injection controls are confined to test workers/routes.

| Confirmed defect                                                                 | Evidence and correction                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Direct reopen/export could bypass expiry filtering                               | Original direct-open regression returned an expired checkpoint. `open()` and reconciliation now reject expired/discard records, including expiry reached during rehash.                                                                                                                                                          |
| Late receipt/ledger/reconcile callback recreated deleted metadata                | Original delayed receipt test restored a row after purge. IDB updates now require an existing matching storage/manifest incarnation and cannot reverse a tombstone; actual delayed callbacks are rejected.                                                                                                                       |
| Catalog snapshot could delete a renewed receiver/source                          | Controlled snapshots let another worker renew retention before cleanup. Receiver deletion rechecks under its Web Lock/IDB transaction; source expiry is conditional within its own transaction.                                                                                                                                  |
| Concurrent prepares exceeded existing record limits                              | Independent clients reached receiver count 65 and source count 33. Count/insert is atomic for receivers; source eviction/upsert is atomic without changing the 64/32 limits. Rejected receiver preparation leaves no OPFS slot; deleting one frees capacity.                                                                     |
| Transfer-row loss stranded manifest/block records                                | Original cases left metadata with OPFS present or absent. Orphan metadata keys are discovered without loading all block bodies, locked and rechecked before removal. Source records remain independent.                                                                                                                          |
| UUID-named regular files were treated as orphan directories                      | Original sentinel file was removed. Collector now requires directory kind, package namespace and UUID plus missing metadata under lock.                                                                                                                                                                                          |
| One malformed catalog row blocked unrelated recovery/cleanup                     | Original receiver/source schema corruption aborted listing. Entries are validated individually; unknown expiry/identity is not guessed. Valid entries recover, damaged entries remain unavailable with scoped Delete/Forget.                                                                                                     |
| Damaged metadata made even explicit scoped deletion impossible                   | Original explicit purge failed with a schema error. Locked UUID-based tombstoning supports intentional deletion without trusting damaged non-identity fields. Termination after that tombstone is reconciled safely.                                                                                                             |
| Cached Save controls survived failed rehash/deletion                             | Original UI still offered the prepared File after bytes failed validation or deletion failed. Controls are pruned against current finalized evidence and withdrawn before attempting delete.                                                                                                                                     |
| Source reselection bypassed expired metadata                                     | Original direct production-worker RPC accepted expired source metadata. Reselection now requires a retained source/receiver identity. Unused worker File references were removed.                                                                                                                                                |
| Storage RPC disposal/start failures leaked pending work and error classification | A disposed client started RPCs; synchronous `postMessage` failure left a timer/pending request and exposed the thrown text. Calls now fail immediately, clean pending state and use fixed messages. Busy/quota/integrity categories survive worker boundaries. Unknown capacity is unavailable, not a false disk-full diagnosis. |

Preparation interrupted before the storage-key child existed also required an unnecessary second orphan pass. Purge now removes the already validated transfer root directly, giving a single deterministic cleanup. These are storage/data-lifecycle defects, not evidence of remote compromise or physical secure-erasure guarantees.

## Limits, CI and safety

Cleanup requires later app/storage access. A closed/suspended browser cannot promise clock-driven deletion. Browser/OS eviction may remove valid data earlier. Strict IDB durability and OPFS flush do not guarantee physical power-loss survival or secure erasure. Exported Downloads/Files/shares are outside app cleanup. A compromised origin/profile can replace both data and expected metadata. Unparseable records without provable expiry are preserved for explicit deletion, not silently destroyed. Namespace/API denial may prevent cleanup until permission/access returns. Legacy/unrelated namespaces remain untouched.

Desktop Chromium and mobile-viewport Chromium tests are engine evidence, not physical Android/iOS, native Safari, browser-kill under real OS pressure or power-cut certification. Task 13's external device gaps remain. The new browser process tests use real process exit/reopen but controlled local files/networks. No test restores or manufactures network authority.
