# Phase 8 security review

Reviewed 2026-10-18 against P8.1–P8.6 of the supplied implementation plan and the architecture's control/data-plane boundary. This is a repository review with reproducible negative tests, not an independent penetration-test certification. The [phase report](reports/phase-8.md) records results and the [privacy model](privacy-model.md) records disclosure and retention limits.

## Trust boundaries

| Boundary / attacker                 | Enforced behavior                                                                                                                          | Verification                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Internet caller → Worker            | Exact HTTPS/loopback origin and method policy, no session query parameters, strict JSON, edge creation/request limits                      | Worker integration suite                                                          |
| Copied invitation → room            | Scoped verifier, short expiry, immutable first candidate, explicit owner decision, maximum two participant records                         | Expired/wrong-room/third-peer/impersonation/revocation tests                      |
| Browser → signaling socket          | One-use origin/revision/epoch-bound tickets in subprotocols; membership and socket generation rechecked after hibernation                  | Repeat-ticket, replacement and persisted-runtime tests                            |
| Approved peer → forwarding          | Authenticated room/peer, owner offers and receiver answers, current epoch, increasing sequence and recent-message replay checks            | Role spoof, stale/replay and malformed/oversized integration cases                |
| Signaling service → device          | Bounded receive queue, negotiated WebRTC identity, ephemeral signed controls and independent human code comparison                         | Client flood, pairing mismatch and signed replay browser tests                    |
| Peer → transfer/storage             | Strict manifests, bounded frames and assembler, negotiated geometry, write/readback hash and checkpoint commit before ACK                  | Real malformed DATA demos; existing corruption, quota and cross-store crash tests |
| Local profile → resume              | Rehash surviving blocks; fresh admitted and independently compared epoch; source-authenticated proofs and full-file identity               | Existing reload, forged-checkpoint, wrong-source and resume tests                 |
| Untrusted filename → display/export | NFC labels, portable comparison, no path traversal/device names/hidden bidi controls, distinct flat export names, conservative MIME        | Security path cases and independent two-file downloads                            |
| App → browser/network/reports       | No analytics or application console logging, no-referrer, production CSP, memory-only admission credentials, allowlisted local diagnostics | Production CSP/history/referrer tests and diagnostics redaction/export tests      |

Room ownership is bearer authority. Anyone holding an owner capability can exercise that authority until expiry/revocation; a hash of a file or capability is not independent identity proof. Code comparison must use a separate trusted channel. A compromised origin serving hostile JavaScript can access this origin's files and credentials; CSP does not defend against an attacker who controls the allowed application code.

## Resource contracts

| Resource                            | Bound / behavior                                                                                                                                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Edge requests / creation            | Configured 300 requests and 30 creates per address per 60 seconds; missing bindings fail closed. Provider counters are an abuse filter, not a globally exact quota.                                          |
| Room admission                      | One owner and one candidate/receiver, including rejected candidates; no unlimited participant list                                                                                                           |
| Persisted room budgets              | 180 HTTP requests, 24 ticket mints, 24 socket upgrade attempts, 12 successful epoch advances per minute; four fixed SQLite keys survive eviction/IP changes                                                  |
| Ticket rows                         | At most one unconsumed ticket per peer, explicit 64-row ceiling, expired-row pruning on mint and alarms                                                                                                      |
| Room / invitation / ticket lifetime | Defaults 900 / 300 / 30 seconds; configured maxima 3,600 / 3,600 / 60 seconds (invitation also bounded by room expiry); close/revoke invalidates tickets, and alarms purge rows after the tombstone interval |
| HTTP JSON                           | 8 KiB, 256 chunks including empty chunks, total body deadline 5 seconds; generic errors and nonblocking cancellation                                                                                         |
| Signaling message                   | 64 KiB UTF-8, SDP 48 KiB, ICE candidate 4 KiB, strict variants; 60 peer messages per 10 seconds, three malformed violations close the socket; forbidden/stale/rate violations close immediately              |
| Device queues                       | Signaling 64 messages / 256 KiB; peer receive 4,096 messages / 2 MiB; outgoing signed-control work 64 tasks; pending local ICE 128 candidates and remote ICE 64 candidates                                   |
| File send buffer                    | Transfer frames and signed file controls respect a 512 KiB data-channel buffer bound; lower ping budget and best-effort pongs                                                                                |
| Transfer / recovery                 | Maximum 16 files, 64 GiB total protocol ceiling, 1 MiB verification blocks, negotiated frame cap up to 16 KiB, at most 65,536 ranges before copying/sorting, fixed-size proof pages                          |
| Local reports                       | 10 reports, 512 KiB/report, 4 MiB logical aggregate, seven-day expiry; bounded frames/events; deletion and expiry on access                                                                                  |

The 64 GiB protocol ceiling is not a supported-device size guarantee. Quota preflight, unknown-space limits and foreground/export limits remain in force. Bounded application queues do not establish a maximum for the browser/network/runtime's own internal buffers. Cloudflare's server WebSocket API does not expose a usable browser-style `bufferedAmount`; server message ceilings, rate limits, small membership and room/ticket budgets constrain application forwarding, while transport-level backpressure remains provider-owned. There is no global concurrent-room or spending cap in this phase. Distributed creation, provider ingress cost and volumetric attacks require P9 edge/account operational controls.

New rooms create tables only after trusted initialization. Forged room identifiers can resolve an actor but do not create the application's persistent schema. Existing room schemas migrate on activation, including closed rooms whose alarms must still purge the new budget table.

## Files and metadata

Labels are never OPFS paths: storage uses generated identifiers. Relative paths must be NFC, at most 240 UTF-8 bytes and eight components. Absolute/drive/UNC paths, empty/dot components, separators in compatibility-folded components, Windows reserved stems (including superscript/fullwidth variants), controls, lone surrogates, bidi controls and trailing dot/space are rejected. NFKC plus Unicode uppercasing provides a conservative portable collision key; ancestor conflicts and duplicate identities are rejected. This is not a complete Unicode visual-spoof detector.

Export flattens directories. A manifest containing `one/a.txt` and `two/a.txt` receives distinct names, with all original basenames reserved before suffix allocation. Names remain safe and byte-bounded. Native save dialogs and the browser/OS handle conflicts with files already outside the application; the app does not silently open and truncate arbitrary destination paths.

Manifests accept no MIME field or unknown metadata. React renders labels as text. Export ignores a source File's MIME claim, uses a small extension map for common non-script document/media types and uses `application/octet-stream` for unknown/HTML/SVG types. Files are never automatically previewed or executed. Exporting a malicious file does not make it safe to open in another application.

## Browser and release controls

Production preview and generated `_headers` enforce same-origin scripts/workers/styles/connections, deny inline/eval scripts, foreign connections, objects, embedding and base-URL changes, and suppress referrers. Camera and sharing permissions are limited to this origin; unused device permissions are disabled. Development relaxes inline script/style policy for React refresh and Vite style injection. The generated static-host policy includes HSTS; public HTTPS, host header propagation, API/upgrade behavior and relay routing still require P9 deployment verification. Static host headers do not automatically apply to Worker responses, which set their own no-store/nosniff/no-referrer/CSP/frame/permissions/CORS policy.

QR code is an origin-local lazy build chunk from exact, lockfile-audited packages; the standalone UMD with an incomplete embedded version manifest was removed. License notices remain. A stronger detector and one bounded front-facing-code fallback handle scaled QR cases missed by the default detector; deterministic public fixtures and production-CSP camera checks cover the migration. Vite 7.3.7, Vitest 4.1.11 and esbuild 0.28.1 replace affected tool versions. A targeted pnpm esbuild override covers Wrangler's older development dependency too; Worker dry-run and integration tests check that override. CI runs `pnpm audit:release` and the generated abuse suite. Audit availability/freshness and unknown vulnerabilities remain limits of registry scanning; a network failure must not be reported as a clean audit.

Automatic CI upload of raw failure artifacts is disabled. Default Playwright network traces/video/screenshots are disabled because automatic failure artifacts can expose invitation capabilities. Explicit reviewed screenshots are used for evidence. Raw test reports remain ignored and must be reviewed before sharing. The secret checker also handles deleted tracked source files before staging, while continuing to reject tracked/unignored environment files and common embedded key patterns.
